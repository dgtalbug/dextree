how it works · two passes

Fast first.
Smart second.

Most semantic indexers make you wait. Dextree gives you a usable graph in under a second from Tree-sitter alone, then quietly upgrades it in the background as LSP resolves types. The graph never stops getting smarter.

Pass 1 — structural. WASM Tree-sitter parses every file and extracts symbols, calls, imports, classes, methods. No types, no resolution. Just shape. Lands in DuckDB as nodes and edges. The graph is queryable in under a second on most repos.

< 1s
accuracy
~85%
cost
$0
Pass 2 — semantic. LSP runs lazily in the background. vscode.executeReferenceProvider resolves call edges to the exact target. Types annotate every node. Diagnostics fold into the graph as quality signals. Edges upgrade in place — no rebuild, no flicker.

how dextree is built

        
Spec-driven.
Agent-executed.

        

          Dextree isn't vibe-coded. Every slice ships from an executable spec
          in .specify/ — written by humans, implemented by agents, reviewed
          against the same spec that created them. Reversible. Reproducible. Auditable.
          The code is an artifact; the spec is the source of truth.
        

      


      

        

          

            

              
              what we don't do
            

            
Pure agentic.

            
    
              
  • "hey Claude, build me a thing"
    • 
              
  • AI improvises, then drifts
    • 
              
  • output isn't reproducible
    • 
              
  • review = reading what was generated
    • 
              
  • rollback = vibes
    • 
            

          

          
vs.

          

            

              
              what we actually do
            

            
Spec-first.

            
    
              
  • human writes spec in .specify/
    • 
              
  • spec gets reviewed and approved before any code
    • 
              
  • agent implements exactly the spec
    • 
              
  • PR is reviewed against the spec, not the diff alone
    • 
              
  • regenerate from spec any time
    •

# PR Risk Report

## Context (graph)

```sql
SELECT n.name, n.file, n.fan_in,
       has_tests(n.id) AS tested
FROM blast_radius('${PR_BRANCH}')
ORDER BY n.fan_in DESC
LIMIT 20;
```

## Ask

You're a senior reviewer. Given the
symbols above, write a 5-bullet risk
report. Flag any untested hot-paths.
End with a verdict: "ship", "caution",
or "hold".

the wall of honest

        
Things that are
broken right now.

        

          Most pre-alpha tools hide their flaws. We put them on the homepage. If you can see
          the bugs, you know exactly what you're signing up for — and you can decide whether
          to wait or to help.
        

      


      

        ✱
        

          Dextree is pre-alpha v0.1. The monorepo scaffold is in, the indexer
          works, the webview renders. None of this is on the VS Code Marketplace yet.
          Below is the honest list of what's known-broken, scoped to ship before v0.2.
          We update this as bugs land and ship.
        

      


      

        

          critical
          

            Webview reload loses graph state
            
Toggling theme inside VS Code reloads the webview and dumps the in-memory layout. Re-querying works; layout doesn't persist.

          

          
fix · v0.1.1

        

        

          critical
          

            Tree-sitter parser leaks on workspace switch
            
Each workspace reactivation spawns a new WASM instance without disposing the previous. Memory climbs ~80MB / switch.

          

          
fix · v0.1.1

        

        

          high
          

            DuckDB write contention on first index
            
Concurrent file walkers hit the same connection; insert throughput drops 4x on cold start. Need a write queue.

          

          
fix · v0.1.2

        

        

          high
          

            No incremental indexing yet
            
File edit triggers full re-parse of the file, not the changed range. Slow on large files until pass 2 lands.

          

          
fix · v0.2

        

        

          high
          

            Sigma.js label overlap at high zoom
            
Node labels collide above 8k nodes. Need force-directed label de-collision or LOD-based label hiding.

          

          
fix · v0.1.2

        

        

          medium
          

            Python parser misses dataclass inheritance
            
Tree-sitter Python grammar doesn't surface @dataclass mixin chains. Edge resolution waits on pass 2.

          

          
fix · v0.2

        

        

          medium
          

            No graph diff between commits
            
Would unlock "what changed structurally between v1 and v2." Specced, not implemented.

two ways to run the spec loop

        
Specs run local.
Or specs run in CI.

        

          Same spec, two execution surfaces. Mode A runs the agent on your machine — fast feedback,
          private repo OK. Mode B runs the agent inside GitHub Actions — async, parallel,
          team-friendly. Pick per slice, not per project.
        

      


      

        

          mode A · local
          
Spec runner on your machine.

          

            You write the spec, you trigger Claude Code in the terminal, the diff lands in
            your working copy. Fastest loop. Best for solo passes and exploratory slices.
          

          

            
1 write .specify/slice-N.md

            
2 → claude code "implement slice-N"

            
3 → diff on local branch

            
4 → review, tweak, push

            
5 → CI verifies against spec

          

          
    
            
  • sub-minute iteration
    • 
            
  • private repos / private models
    • 
            
  • no CI quota burned on drafts
    • 
            
  • blocks your editor while running
    • 
            
  • only one slice at a time
    • 
          

        


        

          mode B · cloud
          
Spec runner in GitHub Actions.

          

            Push a spec, label the issue, walk away. Action wakes, agent implements, PR opens
            against the spec. Multiple slices fan out in parallel. Best for team velocity.
          

          

            
1 open issue with type:slice

            
2 → comment @claude implement this

            
3 → Action runs, agent codes

            
4 → PR opens against spec

            
5 → Copilot reviews, you merge

          

          
    
            
  • your editor stays free
    • 
            
  • N slices in parallel
    • 
            
  • permission-bound, auditable
    • 
            
  • 5–15min round trip
    • 
            
  • burns Action minutes
    •
